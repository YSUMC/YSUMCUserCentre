Server behavior
- Default /.well-known/mc-interop-v1.json and /api/launcher/interop/v1/site
  contain only the site's published own entries. Peer metadata is retained.
- /api/launcher/friends and /api/launcher/interop/v1/friends contain direct
  friends grouped by source. SHA-512 is now preserved alongside SHA-1.
- Existing ysumc/launcher/<version> (<os>) User-Agents without the split-v1
  capability still receive the old aggregated document on either site URL.
- New launchers send X-YSUMC-Catalog: split-v1. Both 200 and 304 site responses
  vary on User-Agent and X-YSUMC-Catalog. Nginx may also add Accept-Encoding.
- Own and legacy document timestamps use separate derived settings; legacy
  retains interop_document_state and own uses interop_site_document_state.
- Friends are never fetched recursively by the desktop. Server synchronization,
  anonymous reads, namespace protections and existing MUTMCL routing remain.

Launcher implementation
- Independently fetches and validates site and friends, each at most 1 MiB,
  with separate persistent raw snapshots/ETags in managed_manifest_cache.
- Converts grouped friend metadata back into existing source fields, preserving
  namespaced IDs, SHA-512-only packs, stale flags and server-only instances.
- Friends replace any legacy source entries during rolling deployment so IDs
  do not duplicate. A valid empty friends list withdraws those entries.
- Any site/friends/home fetch failure uses the outer complete offline snapshot;
  failed requests do not retire friends or authorize fresh installs/updates.
- The original own manifest still supplies official publications and policy.
- No migration, version bump, announcement, installer or update release created.
